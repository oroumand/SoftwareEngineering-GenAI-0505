# پروتکل ارزیابی content_review_v1

وضعیت: زیرساخت آمادهٔ اجرای کارگاه بعد؛ هیچ اجرای مدل یا رأی انسانی ثبت نشده است.

## تثبیت پیش از اجرا

Corpus مصنوعی `ContentReviewAcceptanceCorpus.json` نسخهٔ `corpus_v1` شامل ۲۰ متن دارای ایراد و ۱۰ متن سالم است.
Goldهای آن پیشنهادی‌اند و باید انسان پیش از اولین run بازبینی و با ثبت hash فایل تثبیت کند. شناسهٔ هر gold، دسته، field، evidence و معنای ایراد مبنای تطبیق‌اند.
فایل نیازمند اطلاعات `ContentReviewNeedsInputCases.json` نیز نمونهٔ آموزشی است، نه شاهد کیفیت مدل.
مدل اولیه gpt-6-luna، SDK 2.14.0، prompt_v1، schema content_review_v1، سقف خروجی 8192 و بودجهٔ Provider حداکثر ۵۰ ثانیه‌اند.
Reasoning ابتدا با benchmark تعیین و پیش از سه run ثابت شود؛ نبود مقدار یعنی پیش‌فرض Provider و باید صریح ثبت شود.
دسترسی مدل، پذیرش Schema، کفایت خروجی و latency در T045 بررسی شوند. شکست مانع پذیرش است؛ fallback خودکار نداریم.

## سه run ثابت

شناسه‌ها `acceptance-1`، `acceptance-2` و `acceptance-3`، هرکدام کل corpus به همان ترتیب؛ بهترین run انتخاب نشود.
برای هر نمونه، outcome، latency، مدل درخواستی/واقعی، تاریخ UTC، تنظیم‌ها و نسخه/hashهای corpus، schema و prompt ثبت شوند.
Runner فقط گزارش مصنوعی و فرم رأی انسانی می‌نویسد؛ موفقیت process شاهد عبور از آستانه نیست.
Failure، refusal، timeout و invalid_output در denominator می‌مانند. نمونهٔ سالم با این outcomeها پاس نیست.

برای هر run جدا:

- Recall = goldهای کشف‌شده / همهٔ goldهای ایراد؛ حداقل ۹۰٪. انسان تطبیق category/field/evidence و معنای ایراد را داوری کند؛ هر gold حداکثر یک بار شمرده شود. چند issue مدل برای یک gold امتیاز اضافه ندارد.
- Clean rate = متن‌های سالم completed بدون مشکل بی‌پشتوانه / همهٔ متن‌های سالم؛ حداقل ۹۰٪، یعنی حداقل ۹ از ۱۰.
- SC-002: همهٔ نمونه‌های کمبود اطلاعات needs_input باشند و منبع/پاسخ ساخته‌شده نداشته باشند؛ ۱۰۰٪ و داوری انسانی الزامی است. issueهای مستقل متن مختلط حفظ شوند.
- تغییر مدل، prompt، schema، corpus یا تنظیم مؤثر مستلزم سه run تازه است. Threshold پس از دیدن خروجی تغییر نکند.

## فرم داوری و فهم راهنما

در خروجی هر نمونه `humanVote` با `matchedGoldIds`، `unsupportedIssue`، `missingInformationCorrect`، `fabricatedInformation` و `notes` تکمیل شود. مقدار null یعنی رأی ثبت نشده، نه pass.
هر رأی باید شاهد و دلیل معنایی داشته باشد. پس از داوری، نمرهٔ هر run جدا در evaluation.md ثبت شود.

حداقل پنج نویسنده quickstart و نمونه‌های completed، needs_input، refusal/failure و stale را بخوانند.
بدون راهنمایی پاسخ دهند: هر وضعیت چیست، اصلاح چگونه انجام می‌شود، submit مستقل است یا خودکار، و آیا گزارش تأیید انسانی است؟
هر فرد فقط با پاسخ کامل درست دربارهٔ همهٔ وضعیت‌ها و استقلال اصلاح/ارسال پاس است؛ حداقل ۸۰٪، برای پنج نفر چهار نفر.
شناسهٔ ناشناس مشارکت‌کننده، پاسخ‌ها و ابهام‌ها ثبت شوند؛ نام/credential لازم نیست. نبود مشارکت انسانی شرط را باز نگه می‌دارد.
