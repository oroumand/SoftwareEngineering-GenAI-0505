# قابلیت ۰۰۴ — آماده‌سازی دانش تحریریه برای RAG (گام ۲۳)

**وضعیت:** پیاده‌سازی آموزشی Ingestion؛ Build، Validation و Acceptance نهایی هنوز تأیید نشده‌اند.

## مسئله

گام ۲۲ نحوهٔ استفادهٔ کنترل‌شدهٔ مدل از یک Tool خواندنی را نشان می‌دهد؛ اما اطلاعاتی
خارج از متن پست یا حافظهٔ مدل ارائه نمی‌کند. برای بررسی محتوای پست در برابر سیاست‌های
تحریریه، باید منبع قابل‌ردیابی و به‌روز به شکل قابل جست‌وجو آماده شود.

## تصمیم طراحی این گام

- یک سند فارسی ساختگی، مستقل از محتوای خصوصی کاربران، در docs/editorial نگهداری می‌شود.
- فایل ورودی با مسیر ثابت انتخاب می‌شود؛ CLI هیچ فایل دلخواه کاربر را ایندکس نمی‌کند.
- بخش‌بندی Semantic بر اساس عنوان‌های Markdown سطح دوم است؛ بخش خالی و بزرگ‌تر از
  ۲۰۰۰ نویسه رد می‌شوند؛ تقسیم نابجا یا کوتاه‌سازی ساکت نداریم.
- برای هر Chunk شناسهٔ پایدار بر پایهٔ شناسهٔ سند، نسخه و شمارهٔ بخش محاسبه می‌شود.
- SHA-256 متن و Metadata شامل DocumentId، Version، Section، Title و EmbeddingModel ثبت می‌شود.
- Embedding توسط OpenAI مدل text-embedding-3-small تولید می‌شود؛ مدل و ابعاد باید
  در سراسر Collection سازگار باشند.
- Collection آموزشی مستقل در Qdrant با معیار Cosine ایجاد یا تنظیم موجود آن کنترل می‌شود.
- تمام Embeddingها پیش از نوشتن نقاط تولید و کنترل می‌شوند؛ سپس Upsert یک‌باره با wait=true انجام می‌شود.
- در اجرای بدون Key یا در خطاهای Provider، عملیات بدون ساخت گزارش موفق خاتمه می‌یابد.
- dry-run فقط بخش‌ها و شناسه‌ها را نمایش می‌دهد و هیچ API خارجی را فراخوانی نمی‌کند.
- CLI از نقطهٔ ورود HTTP محصول جداست؛ درخواست نویسنده حق ایندکس کردن منابع را ندارد.

## خروجی قابل نمایش

۱. اجرای dry-run و مشاهدهٔ پنج بخش معنادار بدون تماس بیرونی.
۲. مشاهدهٔ پنج بردار به همراه Payload و شناسه‌های قابل‌ردیابی در Qdrant پس از ingest.
۳. اجرای دوبارهٔ ingest با شناسه‌های پایدار، بدون ایجاد نسخهٔ تکراری از Pointهای یکسان.
۴. رد کردن Collection موجود با ابعاد یا Distance ناسازگار.
۵. اجرای Unit Testها با Fake Embedding و Fake Qdrant HTTP بدون Secret یا شبکه.

## خارج از محدوده

Retrieval، Scoring، Reranking، تولید پاسخ مستند، Agent Loop، MCP و مدیریت کامل
بازنشستگی نسخه‌های قدیمی در این گام پیاده نمی‌شوند. گام ۲۴ مسئول بازیابی خواهد بود.
در این گام تنها یک نسخهٔ آزمایشی سند ایندکس می‌شود؛ ورود اسناد واقعی سازمان نیازمند
تصمیم حاکمیتی دربارهٔ مجوز، نسخه، نگهداری و حذف است.
