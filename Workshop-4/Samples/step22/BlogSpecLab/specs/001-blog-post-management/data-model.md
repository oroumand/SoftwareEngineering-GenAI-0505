# مدل دادهٔ مدیریت و انتشار پست

این مدل طراحی است؛ هنوز جدول یا Migration ایجاد نشده است. مرجع رفتار [spec.md](spec.md) و مرجع تصمیم‌های فنی [research.md](research.md) است.

## UserAccess

| فیلد | نوع مفهومی | قاعده |
| --- | --- | --- |
| UserId | شناسهٔ پایدار انگلیسی | هویت معتبر؛ مستقل از نام نمایشی |
| CanWrite | boolean | مجوز فعلی نویسندگی |
| CanReview | boolean | مجوز فعلی بررسی و تأیید |
| CanPublish | boolean | مجوز فعلی انتشار |
| IsActive | boolean | حساب غیرفعال مجوز عملیاتی ندارد |

مجوزهای بررسی و انتشار در این نسخه به نقش Editor تعلق دارند؛ Author مجوز نویسندگی دارد و یک کاربر می‌تواند هر دو نقش را داشته باشد. این نگاشت در اطلاعات معتبر سمت سرور قرار می‌گیرد، نه Body درخواست. ایجاد حساب و تخصیص نقش رابط عمومی این Feature نیست. مجوز فعلی در هر مورد کاربرد خوانده می‌شود؛ مجوز تاریخی تأییدکننده دوباره برای اعتبار تأیید بررسی نمی‌شود (FR-001، FR-008، FR-013).

## Credential — دادهٔ امنیتی Infrastructure

Credential شامل Id، UserId، TokenHash یکتا، ExpiresAt و RevokedAt nullable است. هر UserAccess می‌تواند چند Credential مستقل داشته باشد؛ این رابطه مجوز جدید ایجاد نمی‌کند. hash از token تصادفی پرآنتروپی محاسبه می‌شود؛ مقدار خام در DB، پاسخ، fixture ثابت یا Log ذخیره نمی‌شود. Credential منقضی یا لغوشده هویت معتبر ایجاد نمی‌کند. حذف یا لغو دسترسی نباید اطلاعات تاریخی مالکیت و تصمیم‌ها را حذف کند. hash پیشنهادی SHA-256 برای این token تصادفی است؛ سامانهٔ رمز عبور در دامنه وجود ندارد.

## Post — ریشهٔ Aggregate

| فیلد | نوع مفهومی | قاعده |
| --- | --- | --- |
| Id | UUID | تولید سمت سرور |
| OwnerId | UserId | از هویت ایجادکننده؛ ثابت |
| Title / Body | string | غیر null، غیرخالی و غیر whitespace؛ بدون سقف طول کسب‌وکاری ساختگی |
| Status | enum | Draft، PendingReview، ChangesRequested، Approved، Published |
| ContentRevision | integer | از ۱؛ فقط با تغییر واقعی Title یا Body افزایش می‌یابد |
| Version | UUID | توکن رقابت؛ در هر تغییر ذخیره‌شده، از جمله انتقال وضعیت، عوض می‌شود |
| IsDeleted | boolean | خروج منطقی از تمام مسیرهای مشاهده و گردش کار |
| CurrentReviewId | UUID nullable | آخرین تصمیم مرتبط؛ تصمیم‌های قبلی تاریخچه‌اند |
| Publication | PublicationInfo nullable | فقط در Published موجود است |

تفاوت ContentRevision و Version ضروری است: ارسال یا تأیید محتوا را تغییر نمی‌دهد، ولی وضعیت قابل رقابت را تغییر می‌دهد. متن بدون نرمال‌سازی پنهان نگهداری می‌شود؛ مقایسهٔ تغییر واقعی براساس مقدار ذخیره‌شده است. ذخیرهٔ همان متن، تأیید را باطل نمی‌کند. ویرایش واقعی در ChangesRequested همان وضعیت را حفظ می‌کند تا امکان ارسال مجدد و مشاهدهٔ دلیل وجود داشته باشد؛ ویرایش در PendingReview یا Approved به Draft برمی‌گردد. دلیل تاریخی برگشت حفظ می‌شود و به‌عنوان دلیل تصمیم قبلی نمایش داده می‌شود.

## ReviewDecision

| فیلد | نوع مفهومی | قاعده |
| --- | --- | --- |
| Id / PostId | UUID | هر تصمیم متعلق به یک Post |
| ContentRevision | integer | نسخهٔ دقیق بررسی‌شده |
| ReviewedTitle / ReviewedBody | string | Snapshot عنوان و متن در زمان تصمیم |
| Decision | enum | Approve یا RequestChanges |
| ReviewerId | UserId | هویت معتبر تصمیم‌گیرنده |
| DecidedAt | UTC timestamp | تولید سمت سرور |
| Reason | string nullable | برای RequestChanges غیرخالی و غیر whitespace |

تصمیم ثبت‌شده تغییر نمی‌کند. ثبت تصمیم و انتقال Post در یک Commit اتمی انجام می‌شود. تأیید فقط وقتی معتبر است که آخرین تصمیم جاری Approve، نسخه و Snapshot مطابق محتوا، و ReviewerId متفاوت از OwnerId باشد. وجود مجوز در زمان تأیید در مسیر قابل اعتماد Application بررسی می‌شود. لغو مجوز بعدی، تصمیم قبلی را تغییر نمی‌دهد. نیاز به تاریخچهٔ نسخه‌های کامل پست، Event Sourcing یا سامانهٔ Audit عمومی تعریف نشده است.

## PublicationInfo

PublicationInfo بخشی از Post است: PublisherId، PublishedAt به UTC و ApprovedReviewId. محتوای منتشرشده همان Title و Body ثابت پست و ContentRevision تأییدشده است. نیازی به کپی سوم محتوا نیست، زیرا ویرایش و حذف پس از انتشار ممنوع است. رابطه با ReviewDecision باید به تأیید معتبر همین Post اشاره کند. زمان و منتشرکننده در تکرار انتشار تغییر نمی‌کنند.

## انتقال‌های مجاز

| اقدام | وضعیت آغاز | وضعیت پایان | شرط اصلی |
| --- | --- | --- | --- |
| Create | وجود ندارد | Draft | نویسندهٔ فعلی، متن معتبر |
| Edit | Draft / ChangesRequested | همان وضعیت | مالک دارای مجوز، متن معتبر |
| Edit با تغییر واقعی | PendingReview / Approved | Draft | مالک دارای مجوز؛ ابطال تأیید جاری |
| Submit | Draft / ChangesRequested | PendingReview | مالک دارای مجوز، متن معتبر |
| RequestChanges | PendingReview | ChangesRequested | ویراستار فعلی، دلیل معتبر |
| Approve | PendingReview | Approved | ویراستار فعلی غیرمالک |
| Publish | Approved | Published | مجوز فعلی انتشار و تأیید معتبر محتوا |
| Delete | هر وضعیت غیر Published | خروج منطقی | مالک دارای مجوز |

هر انتقال دیگر رد می‌شود. Publish تکراری توسط کاربر مجاز، با تأیید مستقل وضعیت Published، نتیجهٔ انتشار موجود را برمی‌گرداند؛ تأیید یا ارسال تکراری انتقال تازه ایجاد نمی‌کند. کاربر دو نقشی می‌تواند پست خود را با تأیید شخص دیگر منتشر کند. برگشت پست خود توسط Editor ممنوعیت تازه‌ای ندارد؛ ممنوعیت FR-014 مختص خودتأییدی است.

## ذخیره‌سازی و رقابت

Post به چند ReviewDecision و حداکثر یک PublicationInfo مرتبط است. داده‌های هویت موردنیاز به UserAccess ارجاع دارند؛ حذف هویت نباید مالکیت یا اطلاعات تصمیم و انتشار را از بین ببرد. Post و تصمیم جدید در یک تراکنش ذخیره می‌شوند و UPDATE مشروط به Version خوانده‌شده است. رقابت ناموفق هیچ تصمیم یا اطلاعات انتشار مستقلی باقی نمی‌گذارد. IsDeleted نیز همان کنترل Version را دارد. هر درخواست تغییردهنده Version مشاهده‌شده را می‌فرستد؛ بازخوانی و اجرای خودکار فرمان شکست‌خورده ممنوع است. کاربر مجاز پس از تعارض دوباره وضعیت را می‌خواند.

تاریخ‌ها در Persistence با نمایش UTC قابل مقایسه ذخیره می‌شوند؛ انتخاب نگاشت سازگار SQLite در Infrastructure است. ایندکس‌های OwnerId/IsDeleted و Status/IsDeleted برای فهرست‌های این Feature کافی‌اند؛ تضمین ظرفیت یا SLA از آن‌ها استنتاج نمی‌شود.
