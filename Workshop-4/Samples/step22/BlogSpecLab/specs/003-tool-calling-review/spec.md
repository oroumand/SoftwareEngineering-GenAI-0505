# قابلیت ۰۰۳ — بازبینی کمکی با Tool Calling (گام ۲۲)

**وضعیت:** پیاده‌سازی آموزشی؛ Validation و Acceptance نهایی هنوز انجام نشده‌اند.

## مسئله و هدف

قابلیت ۰۰۲، عنوان و متن پست را به مدل می‌فرستد و خروجی را مطابق قرارداد Structured Output دریافت می‌کند.
در گام ۲۲ یک مسیر اختیاری برای نمایش **Function Calling واقعی** اضافه می‌شود، بدون تغییر رفتار مسیر قبلی.

## سناریوی نویسنده

نویسندهٔ دارای مجوز، برای پست خودش در وضعیت Draft یا ChangesRequested درخواست
POST /api/author/posts/{id}/content-review-tools را بدون Body ثبت می‌کند.
Application پیش از تماس با مدل، هویت، مالکیت، مجوز جاری و وضعیت پست را بررسی می‌کند.
مدل در درخواست اول فقط تعریف ابزار read_current_post را دریافت می‌کند، نه عنوان و متن را.
مدل باید یک Tool Call با آرگومان scope=current_post بسازد.
Runtime ساختار و مقدار آرگومان را کنترل می‌کند و تنها Snapshot از قبل مجاز را به‌صورت Tool Result برمی‌گرداند.
در درخواست دوم، مدل باید گزارش بازبینی را طبق JSON Schema نسخهٔ content_review_v1 تولید کند.
Application، گزارش، شواهد و Content Revision را مثل قابلیت قبلی مستقل کنترل می‌کند.

## معیارهای قابل‌آزمون

- مسیر content-review قبلی باید بدون تغییر رفتاری باقی بماند.
- برای کاربر غیرمجاز یا پست نامعتبر، ابزار یا Provider نباید اجرا شود.
- فقط یک فراخوانی ابزار خواندنی با نام و آرگومان محدود پذیرفته شود؛ نام ناشناخته، فیلد اضافی یا JSON ناسازگار Fail Closed شود.
- تماس اول فاقد Title/Body باشد؛ تماس دوم فقط خروجی Tool مجاز را وارد Context کند.
- خروجی نهایی باید همان قرارداد Structured Output را رعایت کند و Validator مستقل Application همچنان اجرا شود.
- هیچ عملیات نوشتنی، ارسال برای بازبینی، تأیید یا انتشار در این ابزار وجود نداشته باشد.
- Refusal، Timeout، InvalidOutput و Unavailable نباید به موفقیت تبدیل شوند.
- کنترل دسترسی دوباره پس از نتیجهٔ مدل، Deadline و Scope مستقل درخواست حفظ شوند.
- راه‌اندازی مسیر Tool Calling نباید به اجرای CRUD قبلی وابسته شود.

## خارج از محدودهٔ این مرحله

Qdrant، RAG، MCP، حلقهٔ پویای Agent، منابع معتبر تحریریه و Acceptance نهایی
در این گام پیاده‌سازی نمی‌شوند. هدف فقط نشان دادن یک Tool Call کنترل‌شده است.
