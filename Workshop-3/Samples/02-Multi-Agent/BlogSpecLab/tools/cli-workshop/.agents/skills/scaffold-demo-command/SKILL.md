# تولید اسکلت آموزشی

از ریشهٔ همین آزمایشگاه که فایل `.cli-lab` و پروژهٔ زیر را دارد اجرا کن. از ریشهٔ پروژهٔ اصلی اجرا نکن. اگر ریشه روشن نیست، ابتدا آن را پیدا کن؛ مسیر یا ابزار جایگزین حدس نزن.

این مهارت فقط روش استفاده از ابزار را تعریف می‌کند؛ محدودیت‌های فایل و مسیر را خود CLI نیز اعمال می‌کند.

## ورودی و اجرا

نام پایه مانند `CreatePost` باید با حرف بزرگ انگلیسی شروع شود و حداکثر ۶۴ حرف و رقم انگلیسی داشته باشد. مسیر باید نسبی و زیر `samples/<folder>` باشد. دادهٔ واقعی، اطلاعات شخصی یا نام‌های محرمانه را در نمونه نگذار.

ابتدا راهنمای ابزار را بررسی کن و پیش‌نمایش بگیر. آرگومان‌ها را جدا و با نقل‌قول امن به برنامه بده؛ متن ورودی را به فرمان قابل اجرا تبدیل نکن.

```powershell
dotnet run --project src/WorkshopCli/WorkshopCli.csproj -- --help
dotnet run --project src/WorkshopCli/WorkshopCli.csproj -- command --name CreatePost --output samples/demo --dry-run
```

اگر کاربر صرفاً پیش‌نمایش خواسته است، همین‌جا پایان بده. در غیر این صورت، فقط پس از موفقیت پیش‌نمایش و تطبیق نام و مسیر با درخواست، همان فرمان را بدون گزینهٔ پیش‌نمایش اجرا کن:

```powershell
dotnet run --project src/WorkshopCli/WorkshopCli.csproj -- command --name CreatePost --output samples/demo
```

خروجی استاندارد، خطا و کد خروج را بررسی کن. صرف دیدن فایل یا پیام ساخت، شاهد موفقیت کامل نیست. فایل‌های گزارش‌شده را بخوان و مطمئن شو دو اسکلت در مسیر مجاز ساخته شده‌اند. Handler هنوز پیاده‌سازی نشده است؛ منطق کسب‌وکار اضافه نکن.

## شکست و توقف

هر شکست Build، اجرای CLI یا پیش‌نمایش، هر کد خروج غیرصفر، یا فایل خروجی ناقص: تولید را متوقف کن و خطا، مرحله و وضعیت فایل‌ها را به کاربر گزارش بده.

تولید دستی جایگزین ممنوع است. برای دور زدن شکست، از ویرایشگر، اسکریپت، قالب دیگر، تغییر نام یا مسیر، حذف فایل موجود، گزینهٔ بازنویسی یا اصلاح خود ابزار استفاده نکن. خطا را موفقیت اعلام نکن. اگر خطای ورودی روشن است، ورودی اصلاح‌شده را پیشنهاد بده؛ اجرای مجدد پس از شکست نیازمند درخواست تازهٔ کاربر است. در خطای فایل‌سیستم ممکن است خروجی ناقص مانده باشد؛ آن را خودکار پاک یا تکمیل نکن.

کد خروج صفر یعنی اجرای موفق یا پیش‌نمایش معتبر؛ کد ۲ یعنی ورودی، مسیر یا ریشهٔ نامعتبر؛ کد ۳ یعنی برخورد با فایل/پوشهٔ موجود؛ کد ۴ یعنی خطای دسترسی یا ورودی/خروجی. خطای ابزارهای میزبان مانند `dotnet` ممکن است کد متفاوتی داشته باشد و همان قاعدهٔ توقف را دارد.

## گزارش

نام و مسیر نسبی، پیش‌نمایش یا اجرای واقعی، کد خروج، فایل‌های ساخته‌شده و بررسی انجام‌شده را گزارش کن. تست ابزار با دستور زیر اجرا می‌شود؛ این پروژه یک اجراگر آزمون مستقل است و با `dotnet test` اجرا نمی‌شود:

```powershell
dotnet run --project tests/WorkshopCli.Tests/WorkshopCli.Tests.csproj
```

این متن راهنمای عامل است، نه مرز امنیتی سخت. از تضمین تبعیت همهٔ عامل‌ها یا آمادگی کد برای محصول ادعا نکن.
