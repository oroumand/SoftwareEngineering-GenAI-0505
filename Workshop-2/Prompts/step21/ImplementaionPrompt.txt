`$speckit-implement`

تمام بخش‌های کدنویسی و آماده‌سازی Feature فعال `002-ai-content-review` را براساس `tasks.md`، Specification، Plan، Research، قراردادها، Constitution و Technical Baseline پیاده‌سازی کن.

در این مرحله قصد داریم کدنویسی Feature را کامل کنیم، اما اجرای تست‌ها، Evaluation واقعی و تأیید نهایی عملکرد عمداً به کارگاه بعدی موکول شده است.

## دامنهٔ اجرا

تمام Taskهای قابل پیاده‌سازی را انجام بده، شامل:

- ایجاد و اتصال پروژه `Infra.AI`
- قراردادهای Application
- Reader و projectionهای لازم
- Deadline و Cancellation infrastructure
- Content Review Service
- Validator مستقل
- Prompt نسخه‌دار
- Strict output parser
- OpenAI Responses API adapter
- Structured Output با Schema موجود
- تفکیک completed / needs_input / refusal / failure
- HTTP endpoint و DTOها
- DI و Configuration
- OpenAPI metadata
- Data Minimization و حفاظت Logging
- Freshness و recheck
- مدیریت concurrency و timeout
- راهنمای Quickstart و تنظیمات عملیاتی
- تمام Unit/Integration test code
- Fake gateway و test fixtures
- Corpus ارزیابی
- Evaluation protocol
- Provider smoke-test code
- Quality evaluation runner code

تست‌ها و Evaluation infrastructure باید نوشته و آمادهٔ اجرا باشند؛ هدف این است که جلسهٔ بعد بتوانیم مستقیماً وارد Test، Debug، Evaluation و Acceptance شویم.

## دربارهٔ تست‌ها

Taskهایی که می‌گویند Test Code ایجاد شود باید اکنون پیاده‌سازی شوند.

صرفاً به این دلیل که اجرای تست به جلسهٔ بعد موکول شده، نوشتن Test Code را حذف نکن.

بنابراین تست‌های مربوط به:

- Application
- Validator
- Transport
- Protocol
- HTTP
- needs_input
- Non-Mutation
- Concurrency
- Timeout
- Privacy
- Configuration
- OpenAPI
- Provider opt-in
- Quality Eval

باید اکنون وجود داشته باشند.

ولی اجرای Suite و ثبت Pass/Fail نهایی جزو این مرحله نیست.

## Build

در صورت نیاز برای رفع خطاهای compilation یا dependency می‌توانی `restore` و `build` اجرا کنی.

این کار فقط Development Check محسوب می‌شود.

اجرای build را جایگزین Validation، Test یا Acceptance معرفی نکن و به‌دلیل اجرای build، `T049` را تکمیل‌شده علامت نزن.

## OpenAI

طراحی تأییدشده را رعایت کن:

- OpenAI Responses API
- مدل اولیه `gpt-6-luna`
- package رسمی `OpenAI 2.14.0`
- non-streaming
- `store=false`
- بدون Tool Calling
- بدون MCP
- بدون Web Search
- بدون File Search
- بدون RAG
- بدون Agent
- بدون fallback خودکار

Structured Output باید با Schema نسخه‌دار `content_review_v1` انجام شود.

Artifact موجود:

`specs/002-ai-content-review/contracts/model-output.schema.json`

Source of Truth قرارداد Wire باقی بماند.

JSON Mode ساده یا Prompt-only JSON استفاده نشود.

## Task status

هر Taskی که واقعاً پیاده‌سازی آن تمام شد در `tasks.md` به `[X]` تغییر کند.

هشت Task تعویق‌داده‌شده باید `[ ]` باقی بمانند.

اگر Task دیگری بدون اجرای تست/Eval قابل تکمیل نیست، نتیجهٔ ساختگی ایجاد نکن؛ آن را باز نگه دار و در گزارش نهایی دلیلش را مشخص کن.

## محدودیت مرحله

Feature بعدی را شروع نکن.

Tool Calling، MCP، RAG، Qdrant و Agent وارد این Feature نشوند.

Constitution و تصمیم‌های تثبیت‌شدهٔ Technical Baseline را تغییر نده، مگر اینکه یک تعارض واقعی کشف شود؛ در آن صورت خودکار اصلاح نکن و فقط گزارش بده.
