## مرزهای معماری

در اجرای این فاز موارد زیر الزام‌آورند:

- Authentication فقط هویت معتبر را استخراج کند.
- Authentication نباید به‌تنهایی Permission ایجاد کند.
- Permission جاری باید از منبع معتبر Server-side خوانده شود.
- کنترل Permission مربوط به Use Case در Application انجام شود.
- Client یا Header نباید بتواند نقش، مالکیت یا Permission معتبر ایجاد کند.
- Core نباید به EF Core، ASP.NET Core یا جزئیات HTTP وابسته شود.
- `DbContext` و `IQueryable` نباید به Application یا Domain نشت کنند.
- نتیجه‌های Application باید مستقل از HTTP باشند.
- تبدیل نتیجه به `ProblemDetails` در Api انجام شود.
- Business Logic در AuthenticationHandler، DataAccess یا Api ایجاد نکن.
