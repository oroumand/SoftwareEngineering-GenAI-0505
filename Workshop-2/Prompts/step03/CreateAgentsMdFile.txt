در Root پروژهٔ BlogSpecLab یک فایل با نام AGENTS.md ایجاد کن که راهنمای عملیاتی OpenAI Codex برای کار در این Repository باشد.
این فایل باید کوتاه، دقیق و کاربردی باشد و نقش «نقشهٔ کار Agent در Repository» را داشته باشد؛ نه اینکه تمام مستندات پروژه را در خود تکرار کند.
تمام محتوای متنی فایل باید فارسی باشد. نام فایل‌ها، مسیرها، دستورات، Identifierها و اصطلاحات فنی ضروری می‌توانند انگلیسی باقی بمانند.
۱. معرفی کوتاه پروژه
در ابتدای فایل توضیح بده:
BlogSpecLab یک پروژهٔ آموزشی C# / ASP.NET Core روی .NET 10 است که با رویکرد Specification-Driven Development و Spec Kit توسعه پیدا می‌کند.
پروژه ابتدا به‌صورت یک سامانهٔ معمولی مدیریت و انتشار پست توسعه داده می‌شود و قابلیت‌های هوش مصنوعی بعداً و فقط براساس نیازمندی‌های تأییدشده به آن اضافه خواهند شد.
۲. منابع مرجع پروژه
مشخص کن که Codex پیش از انجام تغییرات مرتبط باید منابع زیر را در نظر بگیرد.
Constitution
مرجع اصلی اصول پایدار پروژه:
.specify/memory/constitution.md
پیش از تصمیم‌های معماری، ایجاد پروژهٔ جدید، تغییر مرزهای مسئولیت یا تغییر جهت وابستگی‌ها، این فایل باید بررسی شود.
قواعد Constitution را داخل AGENTS.md تکرار نکن؛ فقط به آن به‌عنوان Source of Truth ارجاع بده.
Feature Specifications
Specificationها و سایر Artifactهای Featureها از طریق ساختار ایجادشده توسط Spec Kit نگهداری خواهند شد.
هنگام کار روی یک Feature، ابتدا Artifactهای مربوط به همان Feature را پیدا و مطالعه کن.
اگر تغییر رفتاری درخواست شده ولی Specification مربوطه وجود ندارد یا تغییر موردنظر در آن تعریف نشده است، بدون هماهنگی مستقیم وارد پیاده‌سازی رفتار جدید نشو.
۳. روش توسعه
Codex باید هنگام کار در این Repository این Workflow را رعایت کند:
ابتدا محدودهٔ درخواست کاربر را مشخص کن.
Artifactهای SDD مرتبط با همان تغییر را بررسی کن.
در صورت ارتباط تصمیم با اصول پروژه، Constitution را بررسی کن.
فقط تغییرات موردنیاز همان گام را انجام بده.
بدون درخواست کاربر وارد Feature یا مرحلهٔ بعدی SDD نشو.
هنگام وجود ابهام مؤثر بر رفتار یا معماری، آن را گزارش کن و از حدس زدن تصمیم‌های مهم کسب‌وکار خودداری کن.
پس از پیاده‌سازی، بررسی‌ها و آزمون‌های متناسب با تغییر را اجرا کن.
نتیجه، فایل‌های تغییرکرده، آزمون‌های اجراشده و مشکل‌های باقی‌مانده را به‌صورت خلاصه گزارش کن.
۴. قواعد کار با Repository
قواعد عملیاتی زیر را ثبت کن:
فایل‌ها و پروژه‌هایی را که برای گام فعلی لازم نیستند ایجاد نکن.
از Overengineering و ایجاد Abstractionهای زودهنگام خودداری کن.
Package، SDK یا Framework جدید را بدون نیاز مشخص اضافه نکن.
بدون نیازمندی تأییدشده قابلیت جدید ایجاد نکن.
Business Logic را در Endpoint، Infrastructure، Prompt یا Adapter خارجی تکرار نکن.
هنگام تغییر ساختار پروژه‌ها، جهت Project Referenceها را با Constitution کنترل کن.
فایل‌های تولیدشده توسط Spec Kit را بدون دلیل و بدون ارتباط با Workflow جاری تغییر نده.
Secret، API Key و Credential را در کد، مستندات یا Log قرار نده.
اگر درخواست کاربر با Constitution یا Specification تأییدشده تعارض دارد، قبل از انجام تغییر تعارض را گزارش کن.
۵. قواعد کار با Coding Agent
مشخص کن:
تغییرات باید کوچک، قابل بررسی و محدود به Scope درخواست باشند.
Codex نباید به‌صورت خودکار مرحلهٔ بعدی پروژه را اجرا کند.
تولید موفق کد یا Artifact به‌معنای تأیید آن نیست.
برای تصمیم‌های مهم معماری، گزینه‌ها و پیامدهای مهم باید پیش از تغییر گزارش شوند.
از بازنویسی فایل‌های سالم و نامرتبط خودداری شود.
در صورت وجود چند راه‌حل، راه‌حل ساده‌تر و سازگار با Constitution ترجیح داده شود؛ مگر اینکه نیازمندی خلاف آن را ایجاب کند.
۶. زبان و شیوهٔ مستندسازی
قواعد زیر را ثبت کن:
Artifactهای متنی پروژه و توضیحات مستندات به زبان فارسی نوشته شوند.
نام کلاس‌ها، Interfaceها، متدها، Namespaceها، پروژه‌ها و سایر Identifierهای کد به انگلیسی باشند.
اصطلاحات فنی رایج در صورت نیاز می‌توانند به انگلیسی باقی بمانند.
کد و نام‌گذاری فنی نباید فارسی شوند.
توضیحات باید دقیق و مختصر باشند و از مستندسازی تکراری جلوگیری شود.
۷. Build و Test
در نسخهٔ فعلی Repository هنوز Solution و پروژه‌های C# ایجاد نشده‌اند.
بنابراین فعلاً هیچ دستور فرضی برای Build یا Test در AGENTS.md ثبت نکن.
در فایل مشخص کن که پس از ایجاد Solution و پروژه‌های آزمون، دستورات معتبر Build و Test باید به این بخش اضافه شوند.
Codex نباید دستورهایی را برای فایل‌ها یا پروژه‌هایی که هنوز وجود ندارند جعل کند.
۸. تکامل AGENTS.md
در پایان فایل توضیح بده که AGENTS.md یک سند عملیاتی زنده است و باید همراه Repository تکامل پیدا کند.
اما:
قواعد پایدار معماری نباید از Constitution به این فایل منتقل یا در آن کپی شوند.
جزئیات یک Feature نباید در این فایل قرار بگیرند.
مستندات تخصصی آینده باید در فایل مناسب خودشان نگهداری شوند و در صورت نیاز از AGENTS.md به آن‌ها ارجاع داده شود.
از تبدیل AGENTS.md به یک سند بزرگ و شامل تمام دانش پروژه خودداری شود.
محدودیت این مرحله
در این مرحله فقط فایل Root-level AGENTS.md را ایجاد کن.
هیچ فایل دیگری را تغییر نده.
هیچ Solution، پروژهٔ C#، Specification، Plan، Task یا کد برنامه ایجاد نکن.
فایل Constitution را تغییر نده.
در پایان فقط مسیر فایل ایجادشده و خلاصهٔ کوتاهی از بخش‌های آن را گزارش کن.
