# نمونه Vibe Coding

این پروژه «بد» یا خراب ساخته نشده است؛ یک خروجی معمول و ظاهراً قابل قبول از یک prompt کوتاه است. هدف دمو نشان‌دادن چیزهایی است که prompt درباره آن‌ها سکوت کرده است.

## اجرا

```powershell
dotnet run --urls http://localhost:5061
```

سپس درخواست‌های `UserEntry.Vibe.http` را اجرا کنید.

## سؤال‌هایی که بعد از Happy Path بپرسید

- آیا ایمیل تکراری مجاز است؟
- آیا `SARA@example.com` با `sara@example.com` یکی است؟
- حداقل سن چیست و «امروز» از کجا می‌آید؟
- فرمت تلفن چیست؟
- Country نام کشور است یا ISO code؟
- داده با restart چه می‌شود؟
- endpoint چه status codeهایی می‌دهد؟
- خطای داخلی چه اطلاعاتی افشا می‌کند؟
- اگر دو درخواست هم‌زمان برسند چه می‌شود؟
- چرا business rule و HTTP و persistence همگی در یک فایل‌اند؟

این پرسش‌ها ضعف هوشواره نیستند؛ آن‌ها سکوت‌های prompt هستند. Agent برای حرکت‌کردن ناچار است سکوت را با فرض پر کند.
