# از Prompt تا Production

## مهندسی نرم‌افزار در عصر هوش مصنوعی

این مخزن شامل کدها، مثال‌ها، تمرین‌ها، منابع آموزشی و مطالب تکمیلی دوره **«از Prompt تا Production؛ مهندسی نرم‌افزار در عصر هوش مصنوعی»** است.

هدف این دوره، آموزش استفاده حرفه‌ای و قابل‌اعتماد از ابزارها و مدل‌های هوش مصنوعی مولد در فرایند توسعه نرم‌افزار است؛ به‌گونه‌ای که هوش مصنوعی صرفاً به‌عنوان یک ابزار تولید کد استفاده نشود، بلکه در تمام مراحل چرخه توسعه، از تحلیل مسئله و طراحی راهکار تا پیاده‌سازی، تست، بازبینی و مستندسازی، نقشی مؤثر داشته باشد.

> این دوره فراتر از Vibe Coding است و بر کنترل خروجی، اعتبارسنجی، کیفیت فنی و حفظ مسئولیت مهندسی تأکید دارد.

## اهداف دوره

در این دوره تلاش می‌کنیم یاد بگیریم چگونه:

* از GenAI در فرایند واقعی توسعه نرم‌افزار استفاده کنیم.
* Promptهای دقیق، ساختاریافته و قابل ارزیابی طراحی کنیم.
* Context مناسب را در اختیار مدل قرار دهیم.
* خروجی مدل‌های زبانی را بررسی و اعتبارسنجی کنیم.
* از AI برای تولید، بازنویسی و بازبینی کد استفاده کنیم.
* تست‌ها و مستندات فنی را با کمک AI تولید کنیم.
* دانش پروژه و سازمان را با استفاده از RAG به مدل متصل کنیم.
* خطاهایی مانند Hallucination و پاسخ‌های بی‌پشتوانه را کاهش دهیم.
* Agentها و Workflowهای هوشمند و قابل‌کنترل طراحی کنیم.
* مرز مسئولیت میان توسعه‌دهنده و هوش مصنوعی را حفظ کنیم.

## ساختار مخزن

برای هر جلسه یک پوشه مستقل ایجاد می‌شود و تمام منابع مربوط به همان جلسه داخل آن قرار می‌گیرند.

ساختار کلی مخزن به شکل زیر خواهد بود:

```text
.
├── README.md
│
├── Session-01/
│   ├── README.md
│   ├── Slides/
│   ├── Samples/
│   ├── Exercises/
│   ├── Prompts/
│   └── Resources/
│
├── Session-02/
│   ├── README.md
│   ├── Slides/
│   ├── Samples/
│   ├── Exercises/
│   ├── Prompts/
│   └── Resources/
│
└── Session-XX/
    ├── README.md
    ├── Slides/
    ├── Samples/
    ├── Exercises/
    ├── Prompts/
    └── Resources/
```

ساختار هر جلسه ممکن است بر اساس محتوای آن متفاوت باشد، اما معمولاً شامل بخش‌های زیر است:

| مسیر        | توضیح                            |
| ----------- | -------------------------------- |
| `README.md` | معرفی جلسه و راهنمای مطالعه      |
| `Slides`    | اسلایدها و فایل‌های ارائه        |
| `Samples`   | نمونه‌کدها و پروژه‌های آموزشی    |
| `Exercises` | تمرین‌ها و سناریوهای عملی        |
| `Prompts`   | Promptها و قالب‌های مورد استفاده |
| `Resources` | مقالات، منابع و مطالب تکمیلی     |

## نحوه استفاده از مخزن

برای استفاده بهتر از مطالب دوره:

1. ابتدا فایل `README.md` هر جلسه را مطالعه کنید.
2. مفاهیم و مطالب ارائه‌شده در جلسه را مرور کنید.
3. نمونه‌کدهای پوشه `Samples` را اجرا و بررسی کنید.
4. Promptها را آزمایش کرده و خروجی مدل‌های مختلف را مقایسه کنید.
5. تمرین‌های پوشه `Exercises` را شخصاً انجام دهید.
6. خروجی AI را بدون بررسی فنی نپذیرید.
7. نتایج را از نظر صحت، امنیت، خوانایی و قابلیت نگهداری ارزیابی کنید.

## رویکرد آموزشی دوره

در این دوره، هوش مصنوعی جایگزین مهندس نرم‌افزار در نظر گرفته نمی‌شود.

مدل‌های هوش مصنوعی می‌توانند در تحلیل، تولید کد، تست، مستندسازی و بازبینی به توسعه‌دهنده کمک کنند؛ اما ممکن است پاسخ‌های نادرست، قدیمی، ناامن یا ناسازگار با معماری پروژه تولید کنند.

به همین دلیل، فرایند پیشنهادی دوره بر چرخه زیر استوار است:

```text
Requirement
    ↓
Analysis
    ↓
Structured Prompt
    ↓
Context and Knowledge Retrieval
    ↓
Design and Code Generation
    ↓
Test Generation
    ↓
Reflection
    ↓
AI Review
    ↓
Human Review
    ↓
Documentation
    ↓
Production-ready Output
```

هدف نهایی، افزایش سرعت تولید کد به هر قیمت نیست؛ بلکه ایجاد یک فرایند توسعه سریع‌تر، دقیق‌تر، قابل‌کنترل‌تر و قابل‌اعتمادتر است.

## پیش‌نیازها

این دوره برای توسعه‌دهندگان و مهندسان نرم‌افزاری طراحی شده است که تجربه عملی برنامه‌نویسی و توسعه پروژه‌های واقعی را دارند.

آشنایی با مفاهیم زیر برای استفاده بهتر از دوره توصیه می‌شود:

* اصول برنامه‌نویسی و طراحی نرم‌افزار
* Git و مدیریت سورس
* تست نرم‌افزار
* معماری و طراحی سیستم
* کار با IDE و ابزارهای توسعه
* مطالعه مستندات فنی انگلیسی

نمونه‌کدهای هر جلسه ممکن است از زبان‌ها، فریم‌ورک‌ها و ابزارهای متفاوتی استفاده کنند. هدف اصلی نمونه‌ها، آموزش مفاهیم و Workflowهای قابل‌تعمیم است.

## نکته مهم درباره خروجی‌های AI

تمام کدها، تحلیل‌ها و پیشنهادهای تولیدشده توسط ابزارهای هوش مصنوعی باید پیش از استفاده در پروژه واقعی بررسی شوند.

هنگام ارزیابی خروجی AI، حداقل موارد زیر را کنترل کنید:

* صحت عملکرد
* سازگاری با نیازمندی‌ها
* امنیت
* کارایی
* خوانایی
* تست‌پذیری
* قابلیت نگهداری
* سازگاری با معماری پروژه
* سازگاری با نسخه کتابخانه‌ها و ابزارها
* نبود APIها یا قابلیت‌های ساختگی

مسئولیت نهایی تصمیم‌های فنی و استفاده از خروجی‌ها بر عهده توسعه‌دهنده و تیم نرم‌افزار است.
